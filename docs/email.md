# Письма восстановления пароля

PartyPhoto отправляет одноразовую ссылку через **Brevo HTTPS API**. На странице
входа нажать «Забыли пароль?», указать почту аккаунта и открыть письмо. Ссылка
действует 30 минут; после успешной смены пароля все сеансы завершаются.

## Бесплатная настройка для Render

1. Создать аккаунт на [Brevo](https://www.brevo.com/) и выбрать **Free**.
   Бесплатный тариф включает транзакционные письма, до 300 отправок в день,
   без банковской карты. PartyPhoto ограничивает запросы восстановления
   до 200 в сутки на весь сайт, чтобы оставить запас.
2. В Brevo открыть **Settings → Senders, Domains, IPs → Senders → Add sender**.
   Указать имя `PartyPhoto` и свою почту, затем подтвердить её кодом из письма.
   Для учебного демо можно использовать Gmail: Brevo заменяет такой адрес
   отправителя своим служебным доменом. Это временный вариант провайдера;
   для постоянного сервиса нужен свой подтверждённый домен.
3. В **SMTP & API → API Keys** создать отдельный ключ для PartyPhoto.
   Нужен API key, а не SMTP key. Не отправлять его в чат или Git.
4. В Render → **partyphoto-demo → Environment → Edit** добавить:

   | Key | Value |
   | --- | --- |
   | `BREVO_API_KEY` | Ключ API из Brevo |
   | `MAIL_FROM_EMAIL` | Подтверждённая почта отправителя |
   | `MAIL_FROM_NAME` | `PartyPhoto` |

   Сохранить через **Save, rebuild, and deploy**. Если код ещё не обновился,
   открыть **Manual Deploy → Deploy latest commit**. Переменные Supabase
   и S3 повторно не добавлять. `APP_URL` на Render берётся из выданной HTTPS-ссылки.
5. После статуса **Live** открыть `/login`, затем «Забыли пароль?».
   Использовать свой уже зарегистрированный **на публичном сайте** email.
   Локальные аккаунты автоматически не переносятся. Проверить письмо и «Спам»,
   перейти по ссылке, задать новый пароль от 8 до 128 символов и войти с ним.
   Повторное использование ссылки должно показать ошибку.

Источники: [бесплатный тариф](https://help.brevo.com/hc/en-us/articles/208589409-About-Brevo-s-pricing-plans),
[подтверждение отправителя](https://help.brevo.com/hc/en-us/articles/208836149-Create-a-new-sender-From-name-and-From-email),
[замена адресов Gmail](https://help.brevo.com/hc/en-us/articles/14925263522578-Comply-with-Gmail-Yahoo-and-Microsoft-s-requirements-for-email-senders),
[Email API](https://developers.brevo.com/reference/send-transac-email).

## Если письмо не приходит

Форма намеренно не раскрывает, зарегистрирован ли email. Успешный ответ формы
означает, что запрос принят; он не подтверждает доставку письма в почтовый ящик.
Проверить адрес аккаунта и «Спам», затем **Brevo → Transactional → Logs**.
Brevo иногда требует активации транзакционной отправки через поддержку:
[инструкция](https://help.brevo.com/hc/en-us/articles/115000188150-Troubleshooting-Issues-with-Brevo-SMTP).

В Render Logs выводятся только безопасные статусы:

- `Password reset email: accepted` — Brevo принял письмо, доставка проверяется в Brevo.
- `failed (unauthorized)` — проверить ключ API.
- `failed (sender_rejected)` — проверить подтверждение отправителя и активацию аккаунта.
- `failed (rate_limited)` — достигнут лимит провайдера.
- `failed (unavailable)` — сетевой сбой, таймаут или ошибка провайдера.
- `failed (internal)` — ошибка приложения/базы.

Адреса получателей, токены и содержимое писем в логи приложения не выводятся.
При отсутствии настроек форма возвращает общую ошибку сервиса.
Таймаут API — 8 секунд; автоматических повторов отправки нет. При сбое
удаляется только токен этой попытки, более новая ссылка сохраняется.
При перезапуске процесса незавершённая отправка может прерваться: это небольшой
учебный сервис без отдельной долговечной очереди писем. Повторить запрос через
минуту; не более трёх запросов в час на один email.

## Локальные проверки без отправки настоящих писем

Требуются локальные PostgreSQL и миграции из обычного `.env`. Не использовать
для этих тестов `.env.demo`. Временно запустить dev-сервер с тестовыми переменными:

```bash
EMAIL_TEST_API_URL=http://127.0.0.1:3119/v3/smtp/email \
BREVO_API_KEY=local-test-key MAIL_FROM_EMAIL=partyphoto@example.invalid \
MAIL_FROM_NAME=PartyPhoto npm run dev
```

В другом терминале:

```bash
npm run test:email
npm run test:forgot-password
npm run test:password-reset
npm run test:ui -- tests/forgot-password.browser.spec.ts tests/password-reset.browser.spec.ts
```

HTTP-тест сам поднимает mock-провайдер на `127.0.0.1:3119`. Тестовый endpoint
разрешён только в development/test и только на loopback; production отвергает
эту переменную. Интеграционный тест проверяет одинаковые ответы, ограничения,
одноразовую ссылку, смену пароля и отзыв сессий. Он не отправляет настоящие письма
и удаляет свои тестовые данные. После проверок перезапустить обычный `npm run dev`.

Чтобы проверить настоящую почту локально, добавить три переменные Brevo в свой
игнорируемый `.env` и перезапустить обычный dev-сервер без тестовых переменных.
Ссылка в таком письме использует локальный `APP_URL`, поэтому открыть её нужно
на том же компьютере. В Docker значения передаются через существующий `env_file`.
