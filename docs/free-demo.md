# Бесплатный запуск для защиты курса

Используем один **Render Free Web Service** для сайта и обработчика ZIP,
**Supabase Free** для PostgreSQL и приватного S3-хранилища. Домен и SSL выдаёт
Render: `https://<имя-сервиса>.onrender.com`. VPS, платный worker и покупка домена
не требуются. Конфигурация находится в `render.yaml`.

Это демо для небольшой галереи, не круглосуточный production. Render засыпает
после 15 минут без входящих запросов, следующий запуск занимает около минуты.
Supabase Free включает 500 МБ БД, 1 ГБ файлов и ограниченный трафик; проект может
приостановиться после недели неактивности. Перед защитой открыть сайт заранее
и проверить состояние проекта Supabase. Не создавать отдельный Render Postgres:
его бесплатная база истекает через 30 дней.

Источники: [Render Free](https://render.com/docs/free),
[Supabase Free](https://supabase.com/pricing).

## 1. Supabase

1. Войти через GitHub на https://supabase.com/dashboard и создать организацию
   на плане **Free**, затем проект `partyphoto-demo`. Регион — Frankfurt или
   ближайший доступный европейский. Пароль БД сохранить в менеджере паролей.
2. В **Connect → Session pooler** скопировать PostgreSQL connection string.
   Использовать порт **5432** и username из панели, включая идентификатор проекта.
   Не покупать IPv4 add-on: session pooler уже поддерживает IPv4.
3. Заменить `[YOUR-PASSWORD]` паролем БД, кодируя специальные символы как URL.
   Добавить параметры:
   `?schema=partyphoto&connection_limit=2&pool_timeout=20&sslmode=require`.
   Если строка уже содержит `?`, объединить параметры, оставив ровно один `schema`.
   Схема **partyphoto** обязательна: таблицы аккаунтов не должны попасть в
   публичный Data API. Не добавлять её в список exposed schemas Supabase.
4. Создать в **Storage** приватный bucket `partyphoto`, оставить **Public bucket**
   выключенным. Разрешить также ZIP: не задавать ограничение MIME только картинками.
   Лимит отдельного объекта — 50 МБ или доступный максимум бесплатного плана.
5. В настройках Storage → **S3** создать Access Key ID и Secret Access Key.
   Скопировать также endpoint и region именно из панели. Endpoint выглядит как
   `https://<project-ref>.storage.supabase.co/storage/v1/s3`.
   Эти ключи используются только сервером; не помещать их в `NEXT_PUBLIC_*`, Git или чат.

Дополнительно можно выключить **Data API → Enable Data API**: PartyPhoto обращается
к БД напрямую через Prisma, а фотографии обслуживает через S3. Supabase Auth
не используется — регистрация и вход остаются в самом PartyPhoto.

Источники: [подключение PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres),
[S3 credentials](https://supabase.com/docs/guides/storage/s3/authentication),
[защита Data API](https://supabase.com/docs/guides/api/securing-your-api).

## 2. Render

1. Войти на https://dashboard.render.com через GitHub.
2. **New → Blueprint** → репозиторий `issatayyyy/partyphoto`, ветка `main`.
   Render прочитает `render.yaml`. В списке должен быть ровно один Web Service
   с планом **Free**, без платных ресурсов.
3. Заполнить пять значений из Supabase:

   | Переменная | Значение |
   | --- | --- |
   | `DATABASE_URL` | Session pooler со схемой `partyphoto` и параметрами выше |
   | `S3_ENDPOINT` | Endpoint S3 из Storage settings |
   | `S3_REGION` | Region из тех же S3 settings |
   | `S3_ACCESS_KEY_ID` | Созданный S3 Access Key ID |
   | `S3_SECRET_ACCESS_KEY` | Созданный S3 Secret Access Key |

4. Запустить Blueprint. В пределах бесплатных лимитов стоимость сервисов $0.
   Не выбирать платный workspace/compute plan. Если на аккаунте нет платёжного
   способа, Render при превышении бесплатных лимитов приостанавливает услуги
   вместо списания; точные лимиты видны в Billing → Monthly Included Usage.
5. Дождаться **Live** и открыть выданную HTTPS-ссылку. `APP_URL` автоматически
   берётся из `RENDER_EXTERNAL_URL`; вручную его задавать не нужно. Проверить
   `/api/health/ready`: ожидаются `status: ready`, `database: ok`, `storage: ok`.

Сборка выполняет `npm ci --include=dev`, production build и копирование статики
в standalone. При запуске сначала применяются миграции в схему `partyphoto`,
затем supervisor запускает сайт и worker. При ошибке миграций сайт не запускается.
`preDeployCommand` и Shell/SSH не нужны: эти функции ограничены на Render Free.
Auto-deploy выключен, чтобы случайные изменения `main` не прервали показ проекта.
Для обновления: Render → Manual Deploy → Deploy latest commit.

Для кнопки «Забыли пароль?» отдельно подключить бесплатную отправку через Brevo:
[настройка почты](email.md). В Render добавляются только три новые переменные
`BREVO_API_KEY`, `MAIL_FROM_EMAIL`, `MAIL_FROM_NAME`; повторно импортировать
настройки Supabase не нужно. Без этих настроек сайт работает, но письмо
восстановления отправить нельзя.

## 3. Назначить себе суперадмина

Зарегистрировать свой аккаунт на публичном сайте. Затем локально создать
игнорируемый Git файл `.env.demo` со строкой `DATABASE_URL` этого проекта Supabase.
Содержимое `.env` локального проекта не заменять. Выполнить:

```bash
node --env-file=.env.demo scripts/admin-bootstrap.mjs --email owner@example.com
```

Указать email своего уже зарегистрированного аккаунта. Пароль аккаунта команда
не меняет. Войти снова на публичный сайт и открыть `/admin`. Не создавать
автоматическое назначение ADMIN по email при регистрации: email пока не подтверждается.

## 4. Проверка перед сдачей

Создать один альбом и загрузить 10–20 небольших JPEG/PNG/WebP. Открыть гостевую
ссылку в другом браузере, проверить пароль альбома, загрузку гостями, лайки,
скачивание оригинала и ZIP. Отдельно показать преподавателю `/admin` со своего
аккаунта. Публичная ссылка открывает сайт, но не выдаёт права суперадминистратора.

Демо ограничивает фото **3 МБ и 6 мегапикселями**, обрабатывает по одному фото
одновременно и допускает ZIP до **40 МБ оригиналов / 100 фото**. На бесплатном
небольшом инстансе это снижает расход памяти. Пока сайт спит, worker тоже спит;
при следующем запуске задачи продолжаются из БД. Данные и фото не хранятся на
временном диске Render и не пропадают при перезапуске.

Локальные аккаунты и альбомы автоматически не переносятся. Для проверки облачного
демо лучше создать отдельные учебные альбомы. Если Supabase остановил проект,
возобновить его из Dashboard перед показом.

## Локальная проверка конфигурации

При запущенных локальных PostgreSQL и S3 из `.env`:

```bash
npm run test:demo
npm run build
npm run demo:prepare
npm run test:demo:integration
```

Последняя команда проверяет production-сборку на порту 3108, создаёт временную
схему `partyphoto_test_*` и удаляет только свои тестовые данные. Проверяются
регистрация, гостевая загрузка, ограничения фото, лайк, оригинал и ZIP через worker.
Тест отказывается подключаться к облачным БД и хранилищам. Реальные настройки
Supabase и ограничения памяти Render нужно проверить после публикации.
