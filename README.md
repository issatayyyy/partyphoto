# PartyPhoto

Сервис альбомов мероприятий. **Текущий этап: загрузка, галереи и модерация фотографий.**
Реализованы регистрация и вход, защищённый кабинет, события с кодами/ссылками/QR,
пароли и сроки доступа, загрузка JPEG/PNG/WebP, сжатые превью, гостевая галерея,
скачивание оригиналов и массовая публикация, скрытие и удаление фотографий.
Локальный PostgreSQL и приватное S3-хранилище SeaweedFS подключены.
Фоновый cleanup worker повторяет удаление файлов и очищает зависшие загрузки.
ZIP-архивы, учёт просмотров и публикация на production-сервере остаются следующими
этапами. Docker-конфигурация подготовлена; запуск её полного runtime требует
отдельной проверки на сервере.

## Стек

Next.js 16 / React 19 / TypeScript; PostgreSQL 17 + Prisma 6;
S3 API (локально SeaweedFS 4.48, production R2/AWS S3); Sharp для превью;
отдельный Node worker для очистки; Docker Compose, Nginx, Certbot.
Локальная конфигурация следует [официальному запуску SeaweedFS](https://github.com/seaweedfs/seaweedfs/wiki/Quick-Start-with-weed-mini)
и [настройке закрытых S3 credentials](https://github.com/seaweedfs/seaweedfs/wiki/S3-Credentials).
Prisma CLI и клиент закреплены на одной версии. Перед production выполнить
`npm audit` и устранить применимые предупреждения зависимостей.

## Локальный запуск

Нужны Node.js 22 и Docker Compose 2.24.4+.

```bash
# Только при первом запуске; существующий .env не перезаписывать.
cp -n .env.example .env
npm ci
docker compose up -d db
npm run db:validate
npm run db:deploy
npm run db:generate
```

Если Docker требует системных прав, использовать `sudo docker compose up -d db`.
Затем установить официальный проверяемый бинарник SeaweedFS без `sudo` и запустить
его в отдельном терминале:

```bash
npm run storage:install
npm run storage:dev
```

Установщик поддерживает Linux amd64, фиксирует версию 4.48 и проверяет SHA-256
официального релиза. Бинарник хранится в пользовательском `.local/share/partyphoto`.
Сервер читает S3-ключи из существующего `.env`, создаёт закрытый bucket и слушает
только loopback. Данные, приватная конфигурация и лог находятся в игнорируемом
каталоге `.data/storage/`. Статическая конфигурация имеет приоритет над сохранёнными
учётными записями SeaweedFS; анонимный S3-доступ запрещён.

Во втором терминале:

```bash
npm run storage:check
npm run dev
```

Открыть http://localhost:3000. Для фоновой очистки запустить ещё один процесс:

```bash
npm run worker:media
```

Для одного прохода очистки: `npm run worker:media:once`.

Вместо native SeaweedFS можно запустить `docker compose up -d db storage`.
Предварительно остановить native `storage:dev`, чтобы освободить порт 9000.
Официальный multiarch Docker-образ закреплён по версии и digest; хранилище
использует отдельный volume `seaweed`. Эти два способа используют разные каталоги
данных. Полный контейнерный выпуск с `app` и `worker` описан в `docs/deployment.md`.

Сохранённые миграции применяются через `db:deploy`; новые изменения схемы
оформляются через `npm run db:migrate -- --name <change>`.
Приложение не меняет схему при старте.
Браузер получает фотографии через защищённые API приложения. S3 endpoint и ключи
остаются на сервере: браузеру не нужно разрешать Docker-имя `storage` или получать
доступ к bucket напрямую.

```bash
npm run db:generate
npm run typecheck
npm run build
```

Dockerfile устанавливает закреплённые зависимости через `npm ci`.
Не коммитить `.env` и секреты.

## Авторизация

Открыть http://localhost:3000/register, указать имя, email и пароль длиной
8–128 символов. Новый аккаунт получает роль `ORGANIZER` и автоматически
попадает в `/dashboard`. Для повторного входа: `/login`. Кнопка выхода удаляет
сессию в БД; кабинет без действующей сессии перенаправляет на вход.

`APP_URL` должен совпадать с адресом в браузере: `localhost` и `127.0.0.1`
считаются разными адресами. После изменения `.env` перезапустить dev-сервер.
Локально использовать `npm run dev`; для production (`npm start`) необходим
HTTPS в `APP_URL`. Это включает защищённые cookies и проверку Origin запросов.

Пароли хешируются Argon2id. В БД сохраняется SHA-256 хеш случайного токена
сессии, cookie имеет HttpOnly/SameSite=Lax и живёт 7 дней. Отключённые аккаунты
и истёкшие сессии теряют доступ. Лимит попыток хранится в PostgreSQL и действует
между процессами приложения: 10 входов на email за 15 минут, 5 регистраций
на email за час, 60 регистраций в час и 120 попыток в минуту на весь сервис.
Для public production лимиты нужно согласовать с нагрузкой и добавить
подтверждение email, восстановление пароля и управление аккаунтами.

Проверки выполняются с запущенным `npm run dev` и локальной БД:

```bash
npm run test:auth
npm run test:events
npm run test:media
# Браузерная проверка использует установленный Google Chrome.
npm run test:ui
```

Тесты создают и удаляют только собственные аккаунты с доменом `example.invalid`.
Проверки предназначены для локального HTTP-адреса и используют `.env` проекта.

## Мероприятия

В `/dashboard` нажать «Создать мероприятие», заполнить название и при желании
описание, адрес альбома, даты, пароль и лимиты. После сохранения доступны
гостевая ссылка `/e/{slug}`, случайный код из 8 символов и QR-код (PNG),
который можно скачать. Гость может ввести код на `/join`.
Слаг создаётся автоматически или задаётся вручную: 3–64 латинских символа,
цифры и дефисы. Изменение адреса делает старую ссылку недоступной.

Владельцы и назначенные организаторы меняют настройки своих событий; фотографы
видят назначенные события и гостевые ссылки; администратор видит все события.
Кабинет показывает последние 100 доступных мероприятий. Назначение участников
через интерфейс и административный bootstrap будут добавлены отдельно.

Пароль альбома: 3–128 символов, Argon2id. Гостевой доступ выдаётся на 24 часа
и ограничен сроком жизни альбома. При смене пароля/срока/разрешений загрузки или
скачивания старые гостевые сессии отзываются; изменение названия или описания
сохраняет доступ. Пустой пароль при явном изменении снимает защиту.
Просроченные альбомы закрыты для гостей, настройки доступны организатору.

Лимит фотографий: 1–10000, хранилища: 10–102400 МБ, одного файла: 1–25 МБ.
Снизить квоту ниже занятого/зарезервированного объёма или числа фото нельзя.
Квоты действуют на загрузку: учитываются оригинал, превью и незавершённые операции.
Счётчик скачиваний увеличивается при разрешённой выдаче оригинала через API;
это не подтверждение полной передачи файла. Сбор просмотров будет добавлен отдельно.

## Фотографии

На странице мероприятия выбрать до 20 файлов. Клиент загружает их отдельными
запросами с отображением прогресса и ошибок. Сервер принимает JPEG, PNG и WebP,
проверяет фактическое содержимое, соответствие MIME, размеры и отсутствие анимации.
Максимум — 40 мегапикселей и до 25 МБ на оригинал; лимит события может быть меньше.

Sharp создаёт WebP-превью до 1200×1200 с учётом ориентации, без EXIF. Обработка
происходит внутри запроса загрузки; до двух загрузок обрабатываются одновременно
на процесс приложения. Затем транзакция резервирует место и количество фото,
файлы сохраняются в приватный S3 и запись переводится в опубликованное состояние.
Гостевые фото при включённой проверке получают статус «На проверке» до публикации
командой мероприятия. Организатор и назначенный фотограф могут выбрать до 100 фото
для публикации, скрытия или удаления.

Гость видит только опубликованные снимки. Галерея загружает страницы по 40 фото;
превью загружаются по мере просмотра, фотографии можно открыть крупнее и скачать
в исходном качестве при разрешённом скачивании. API повторно проверяет срок,
пароль и права при запросе оригинала или превью; ключи объектов не передаются клиенту.

Удаление освобождает квоту после удаления обоих файлов. Если S3 временно недоступен,
фотография остаётся скрытой в состоянии удаления, а cleanup worker повторяет
операцию. Он также убирает незавершённые загрузки после истечения их 15-минутного
срока. Worker нужен постоянно работающему выпуску. Пакетный ZIP пока не реализован.

## Структура

```text
src/app/                 Страницы, кабинет, /e, /join и API auth/events/albums/photos
src/components/          Формы, QR/ссылка, гостевой вход, загрузка и галерея
src/lib/auth*.ts         Сессии, проверка запросов, валидация и лимиты
src/lib/password.ts      Хеширование и проверка паролей
src/lib/events.ts        События, права, валидация и настройки
src/lib/albums.ts        Пароли, гостевые сессии и срок доступа
src/lib/db.ts            Prisma client
src/lib/photos.ts        Загрузка, квоты, модерация и защищённая выдача медиа
src/lib/storage.ts       Серверный S3 client
scripts/media-worker.mjs Фоновая очистка зависших загрузок и удалений
scripts/media-recovery.mjs Идемпотентное удаление S3-объектов и освобождение квот
prisma/schema.prisma     Модель данных
prisma/migrations/       Версии схемы, гостевые сессии и резервирование загрузок
tests/                   HTTP/БД/S3 и браузерные проверки
docs/architecture.md     Связи, права, потоки и этапы разработки
docs/deployment.md       VPS, DNS, TLS, резервное копирование
infra/nginx/             Конфигурация обратного прокси
infra/storage/           Проверяемый installer, приватный S3 и проверка доступа
compose.yaml             Локальная инфраструктура
compose.production.yaml  Настройки для managed S3
Dockerfile               Многоэтапная сборка Next.js
.env.example             Переменные окружения
```
